# OS1 ("Samantha") — Composio Architecture

This document captures how **OS1-HER** uses **Composio (API v3.1)** to provide connectors, skills, proactive triggers, file/inbox sandbox execution, and safety guardrails for a *Her*-inspired personal AI operating system.

---

## 1. System Boundary: Composio vs. OS1 Runtime

Composio does **not** run your LLM, voice loop, or memory/personality layer—your agent runtime stays completely yours. Composio acts as **OS1's nervous system into the user's external digital life**:

| Layer | Owned By | Role in OS1 ("Samantha") |
| --- | --- | --- |
| **Voice, presence, persona, long-term memory** | OS1 Runtime | Realtime audio (e.g., OpenAI Realtime / LiveKit / Gemini Live), emotional continuity, memory graph, proactive attention heuristics |
| **Connectors & OAuth custody** | **Composio Project** | Per-user OAuth flows, token storage/refresh, 1,000+ toolkits, white-labeled Connect Links |
| **Tool discovery & playbooks ("Skills")** | **Composio Sessions + Skills** | Dynamic tool routing (`COMPOSIO_SEARCH_TOOLS`) + automatic multi-step execution playbooks and known pitfalls |
| **Proactive awareness** | **Composio Triggers** | Realtime webhooks when emails, calendar changes, or messages arrive |
| **Heavy file / inbox processing** | **Composio Remote Sandbox** | Persistent Python sandbox + `/mnt/files/` mount for bulk inbox triage, document synthesis, and attachment handling |
| **Trust & safety boundaries** | **Composio Approvals + Firewall** | Voice/UI human-in-the-loop confirmation before outbound/destructive calls, plus prompt-injection filtering on untrusted tool results |

## 2. Project & Environment Isolation

In Composio, a **Project** is the multi-tenancy boundary that scopes API keys, connected accounts, auth configs, webhook subscriptions, saved session configs, and Connect Link branding.

- **Environment separation**: Create dedicated projects per environment (`os1-her-dev`, `os1-her-prod`) in the Composio Dashboard or via `POST /api/v3.1/org/owner/project/new` using an `x-org-api-key`.
- **White-labeled onboarding**: Configure **Project Settings → White Labeling** with App Title `OS1`, the project icon (256–1024px square PNG exported from `assets/icon.svg`), and the OS1 color palette.
  - Applies automatically to every Connect Link generated by `session.authorize()` or `connectedAccounts.link()`.
  - *Note*: Hosted Connect Links remain on `connect.composio.dev`, and provider OAuth consent screens display Composio's managed-app identity unless you attach your own OAuth credentials via a Custom Auth Config.
- **Scoped Project API Keys**:
  - Issue a scoped runtime key with **Session management (Write)** + **Session tool execution (Write)** rather than an unrestricted admin key.
  - Keep `COMPOSIO_API_KEY` and `COMPOSIO_WEBHOOK_SECRET` strictly server-side.
- **User identity**: Always derive `userId` from your authenticated application session (never trust a client-supplied user ID).

## 4. Two-Tier Session Architecture (Voice Latency vs. Deep Work)

In Composio v3.1, all tool execution flows through **Tool Router Sessions** (`composio.sessions.create(userId, config)`). Because a voice-first OS1 cannot afford multi-second meta-tool search round-trips on simple requests, split sessions into two profiles:

### A. Fast Voice Companion Session (`os1-voice-core`)
- **Preset**: `SessionPreset.DIRECT_TOOLS` — exposes a curated, preloaded allowlist (e.g., ~15–25 everyday Gmail, Calendar, Spotify, Tasks tools) directly to the realtime voice model for single-hop execution.
- **Sandbox**: `sandbox: { enable: false }` — strips remote sandbox meta-tools and system prompt overhead.
- **Safety**: Explicit `requireApproval` rules on outbound/destructive tools (e.g., `GMAIL_SEND_EMAIL`, `GMAIL_DELETE_MESSAGE`).
- **Local extensions**: Attach in-process `experimental.localToolkits` for OS1 memory recall, emotional state, and local device actions.
- **Saved Session Configs (`sc_*`)**: Optionally manage the toolkit/tool/tag policy in the Composio Dashboard under **Sessions → Configs** and pass `experimental: { sessionConfigId }`. *(Note: a saved session config cannot be combined with inline `toolkits`, `tools`, `tags`, `localTools`, or `localToolkits` on `create()`.)*

### B. Deep Background Worker Session (`os1-background-worker`)
- **Mode**: Default **Tool Router** — exposes Composio's 7 meta-tools (`COMPOSIO_SEARCH_TOOLS`, `COMPOSIO_GET_TOOL_SCHEMAS`, `COMPOSIO_MULTI_EXECUTE_TOOL`, `COMPOSIO_MANAGE_CONNECTIONS`, `COMPOSIO_WAIT_FOR_CONNECTIONS`, `COMPOSIO_REMOTE_WORKBENCH`, `COMPOSIO_REMOTE_BASH_TOOL`).
- **Scale**: Handles open-ended workflows across 10+ connected apps without flooding the model's context window with hundreds of tool definitions.
- **Sandbox + Files**: `sandbox: { enable: true }` — enables a persistent Python environment and `/mnt/files/` mount (`session.experimental.files.upload/download/list/delete`) for bulk email cleanup, attachment processing, and report/document generation.

## 5. Skills & Custom Capabilities

Three distinct concepts map to "skills" in a Composio-backed OS1 build:

### 1. Composio Built-In Skills (Automatic Playbooks)
When the background agent calls `COMPOSIO_SEARCH_TOOLS` with a natural-language `use_case` (e.g., *"find Catherine's latest email and draft a reply"*), Composio automatically attaches a matching **Skill** alongside the discovered tools:
- `primary_tool_slugs` & `related_tool_slugs`
- `recommended_plan_steps` (ordered multi-step sequence, single-app or cross-app)
- `known_pitfalls` (common API gotchas like passing channel names instead of IDs)

Skills are read-only and active by default—no installation or registration required.

### 2. OS1 Custom Tools & Toolkits
Two ways to extend sessions with OS1-native capabilities:

- **Local Tools & Toolkits** (`experimental.localTools` / `experimental.localToolkits`):
  - **Standalone tools**: In-process OS1 logic with no Composio auth (memory recall/storage, mood state, local notes/files).
  - **Extension tools (`extendsToolkit`)**: Custom wrappers around an existing Composio toolkit that inherit the user's OAuth credentials via `ctx.proxyExecute()`.
  - *Constraint*: Local tools run inside your app process and are **not** available through Composio's hosted MCP endpoint (`mcp: true`).
- **Custom MCP Toolkits** (`composio.customToolkits.create()`):
  - Register your own remote HTTPS MCP server (e.g., an OS1 Memory MCP or Home Assistant MCP) as a `CUSTOM_*` toolkit.
  - Supports `NO_AUTH`, `API_KEY` (`{{generic_api_key}}`), or `DCR_OAUTH`.
  - Scoped to all users in your project (`user_id: "all"`) or private to one user (Pro plan).

### 3. Developer Coding-Agent Skill
To keep coding agents aligned with Composio v3.1 conventions while developing `os1-her`:

```bash
npx skills add ComposioHQ/composio --skill composio -y
```

## 6. Proactive OS1: Realtime Triggers & Attention Triage

Proactive awareness is powered by **Composio Triggers**:

1. **Single project webhook**: Register once via `composio.triggers.setWebhookSubscription({ webhookUrl })` and verify/parse incoming POST payloads using `composio.triggers.parse(request, { verifySecret })` (which enforces HMAC verification and a 300s timestamp replay window).
2. **Realtime delivery**:
   - **Gmail** (`GMAIL_NEW_GMAIL_MESSAGE`, `GMAIL_EMAIL_SENT_TRIGGER`) and **Google Calendar** (`GOOGLECALENDAR_GOOGLE_CALENDAR_EVENT_CREATED_TRIGGER`, `UPDATED`, `CANCELED`, `ATTENDEE_RESPONSE_CHANGED_TRIGGER`) support **realtime webhook delivery** (seconds of latency), along with Slack, Notion, Outlook, Asana, and Twilio.
   - **Scheduled polling**: `GOOGLECALENDAR_EVENT_STARTING_SOON_TRIGGER` polls relative to event start times—ideal for *"Your meeting with Paul is in 10 minutes."*
3. **Local development**: Forward signed events directly to localhost without tunnels using the Composio CLI:
   ```bash
   composio dev triggers listen --forward "http://localhost:8000/api/webhooks/composio"
   ```
4. **Attention Triage Layer (OS1-owned)**:
   - Route incoming trigger events (filtered on `result.rawPayload.type === "composio.trigger.message"` and `result.payload.triggerSlug`) into a lightweight classifier:
     - **Silent / Low**: newsletters, automated receipts → index into OS1 memory or archive.
     - **Ambient / Medium**: calendar rescheduled, non-urgent replies → queue to mention naturally on next conversation.
     - **Interrupt / High**: VIP email, urgent SMS, meeting in 10 min → initiate proactive voice chime or push notification.
   - Handle non-trigger project events (e.g., connection expiry) on the same endpoint to prompt graceful re-authentication.

## 7. Trust & Safety: Approvals (HITL) + Firewall

Never rely solely on system prompts to prevent unauthorized sends, deletes, or prompt-injection attacks from untrusted inbox content.

### Human-in-the-Loop Approvals (`requireApproval`)
*Experimental (`@composio/core` > 0.24.0 / `composio` > 0.27.0)*

- Gate tools explicitly (prefer explicit slugs over hint tags for critical actions):
  ```typescript
  tools: {
    gmail: {
      requireApproval: ["GMAIL_SEND_EMAIL", "GMAIL_DELETE_MESSAGE"],
    },
  },
  tags: {
    requireApproval: ["destructiveHint"],
  },
  ```
- When invoked, `session.execute()` pauses and returns an MCP-format elicitation (`input_requests`) containing the exact tool name and arguments.
- OS1 reads the proposed action aloud (or renders a confirmation card) and re-submits with `approve`, `always_approve` (persists for the rest of the session), or `deny`.
- **Implementation caveats**:
  - Execute gated tools via `session.execute()` directly (framework `handleToolCalls` adapters do not yet handle approval elicitations).
  - If approvals must never be bypassed, disable the remote sandbox (`sandbox: { enable: false }`) on that session, as sandbox script tool calls may not be exhaustively intercepted.

### Firewall (`before_execute` / `after_execute` Hooks)
*Paid plans, usage-based*

- **Built-in prompt-injection defense**: Inspects untrusted tool results (emails, docs, messages) before they reach the LLM.
- **Natural-language condition checks**: Evaluated with full session history (unless Zero Data Retention is enabled). Describe the condition to block, not an instruction:
  - *Before execute*: `"Sending an email containing passwords, API keys, or private financial credentials"`
  - *After execute*: `"An email or document containing a password, API key, or access token"`

## 8. SDK vs. Hosted MCP Decision

**Recommended primary path**: Use the **Composio SDK** (`@composio/core` + provider adapter such as `@composio/vercel`, `@composio/openai`, `@composio/openai-agents`, or `@composio/anthropic`).

Why not hosted MCP (`mcp: true`) as the primary runtime?
- Hosted MCP clients call Composio's server directly, which **bypasses** SDK `beforeExecute`/`afterExecute` modifiers and **cannot run** in-process `localTools` / `localToolkits` (such as OS1's memory or local device tools).
- You can still enable `mcp: true` on any session when you want to bridge that user's session to an external MCP client (Claude Code, Cursor, OpenAI Responses API, etc.).

## 9. Reference Blueprint (TypeScript)

```typescript
import { Composio, SessionPreset } from "@composio/core";
import { VercelProvider } from "@composio/vercel";

const composio = new Composio({
  apiKey: process.env.COMPOSIO_API_KEY,
  provider: new VercelProvider(),
});

// 1. Onboarding: generate a white-labeled OS1 Connect Link
export async function createOnboardingLink(userId: string, toolkit: string) {
  const session = await composio.sessions.create(userId, {
    toolkits: [toolkit],
    manageConnections: true,
  });

  return session.authorize(toolkit, {
    callbackUrl: `${process.env.APP_URL}/onboarding/callback`,
  });
}

// 2. Fast voice companion session (low latency, explicit HITL approvals, no sandbox)
export async function createVoiceSession(userId: string, os1MemoryToolkit: unknown) {
  return composio.sessions.create(userId, {
    sessionPreset: SessionPreset.DIRECT_TOOLS,
    toolkits: {
      enable: ["gmail", "googlecalendar", "spotify", "googletasks"],
    },
    tools: {
      gmail: {
        requireApproval: ["GMAIL_SEND_EMAIL", "GMAIL_DELETE_MESSAGE"],
      },
    },
    authConfigs: process.env.COMPOSIO_SPOTIFY_AUTH_CONFIG_ID
      ? { spotify: process.env.COMPOSIO_SPOTIFY_AUTH_CONFIG_ID }
      : undefined,
    sandbox: { enable: false },
    experimental: {
      localToolkits: [os1MemoryToolkit as never],
    },
  });
}

// 3. Deep background worker session (full Tool Router + Skills + Remote Sandbox)
export async function createBackgroundSession(userId: string) {
  return composio.sessions.create(userId, {
    toolkits: {
      enable: [
        "gmail",
        "googlecalendar",
        "googledrive",
        "googledocs",
        "notion",
        "slack",
        "todoist",
        "spotify",
        "google_maps",
      ],
    },
    manageConnections: true,
    sandbox: { enable: true },
  });
}

// 4. Register project-level webhook subscription (run once per environment)
export async function registerWebhookSubscription() {
  return composio.triggers.setWebhookSubscription({
    webhookUrl: `${process.env.APP_URL}/api/webhooks/composio`,
  });
}

// 5. Webhook handler (Fetch / Next.js App Router / Hono)
export async function handleComposioWebhook(request: Request) {
  const result = await composio.triggers.parse(request, {
    verifySecret: process.env.COMPOSIO_WEBHOOK_SECRET,
  });

  if (result.rawPayload.type === "composio.trigger.message") {
    const { triggerSlug, payload } = result.payload;
    // Route into OS1 Attention Triage service
    console.log("OS1 trigger received:", triggerSlug, payload);
  }

  return Response.json({ status: "ok" });
}
```

## 10. Open Architecture Decisions (Before Scaffolding)

1. **Runtime language & framework**: TypeScript (Node/Bun/Next.js + Vercel AI SDK / OpenAI / Anthropic) vs. Python (FastAPI + LiveKit / OpenAI Agents SDK).
2. **Deployment model**: Single-user personal OS1 (with optional local macOS/desktop bridge) vs. multi-user web/mobile app.
3. **Voice & UI target**: Web app with realtime audio (OpenAI Realtime / LiveKit / Gemini Live), native desktop companion, or text/CLI prototype first.
4. **Phase 1 connectors**: Recommended minimal loop is `GMAIL` + `GOOGLECALENDAR` + `GOOGLEDRIVE` (all managed OAuth with realtime triggers).
